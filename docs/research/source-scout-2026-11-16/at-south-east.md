# Steiermark / Kärnten / Burgenland source scout (2026-11-16)

Research only. Probed with the OkoloBot UA, 1 page + robots.txt (+llms.txt, wp-json where relevant) per site.
Sweep covered all 280 `works` + `llm/empty` rows in these three regions (raw results in the session scratchpad, not committed).
Verdicts: `register-now` = existing adapter/route works today (usually just set `cms` and re-crawl with `--url`); `needs-adapter`; `ask-George`; `avoid`.

## Headline findings

1. **Gemeinde24 platform: 46 of the 280 LLM-route sources** (Murau, Wildon, Mautern, Schöder, Kalwang, Hengsberg, Fernitz-Mellach, Purbach, Mogersdorf, Rudersdorf, Weißensee, ...). Every site serves `/llms.txt` with a machine-readable `## Veranstaltungen` list, one line per event: `- [Title](detail-url) (DD.MM.YYYY, HH:MM Uhr | Ganztägig, Venue): teaser`. Needs ONE new small adapter (`gemeinde24-llms`, ~40 lines). Gemeinde24 robots.txt: `Allow` for normal agents, ClaudeBot/GPTBot/bingbot get `Crawl-delay: 5` and `Disallow: /*?` (no query-strings; llms.txt and /veranstaltungen are fine). Header says "Suchmaschinen und KI-Dienste seriöser Anbieter dürfen die Inhalte lesen" and llms.txt is published for AI assistants. 18-50 entries each (the feed looks capped at ~50). Platform is nationwide (other regions in sources-AT.tsv very likely have more, not counted here).
2. **steiermark.com (Steiermark Tourismus) and burgenland.info are two-hop with schema.org Event on the detail page** (JSON-LD on steiermark.com, Microdata on burgenland.info). robots.txt allows both. Biggest single coverage lever for rural areas.
3. **Citiesapps-hosted municipal sites** (Bruck/Mur, Fürstenfeld, Bad Radkersburg, Wolfsberg, also Feldkirchen, Gleisdorf, Trofaiach, Hartberg, Eisenstadt, Weiz sites embed it) render events in a Vue app. citiesapps.com + customer-domain robots.txt state: crawling/indexing/citing with link is welcome, but "Republishing, aggregating or bulk-copying it into another product ... and TDM are not permitted without a license; rights reserved Art. 4(3) DSM / §42h UrhG. it@citiesapps.com". This is a clear reservation. **Do not crawl; ask George** (licence request is the only clean route; this blocks many bigger towns).
4. Cheap fingerprint wins with existing adapters (no new code): see table A "register-now".
5. Several big-town sites are plain HTML lists with stable markup; each needs a ~30-60 line parser (Kapfenberg, Oberpullendorf, Stainz, Gröbming, Stegersbach, Mürzzuschlag).

## Top 5 recommendations

1. **Gemeinde24 `llms.txt` adapter** (46 sources here, probably 100+ nationwide). One small parser, no JS, robots-friendly, clean title/date/time/venue/URL. Biggest jump in structured coverage; confirm bulk use with Gemeinde24 (office address on gemeinde24.at).
2. **steiermark.com and burgenland.info via two-hop** list -> detail (JSON-LD / Microdata Event). Two registrations cover most of the region incl. bigger towns we cannot crawl directly (Citiesapps). Use `/erleben/veranstaltungen/familie-kinder` on burgenland.info first.
3. **Set `cms` on already-supported platforms**: gem2go (Weiz, Ferlach, Glanegg, Griffen, Oberloisdorf, Oberschützen, St. Kanzian, Pirching), jevents (Aich, Strallegg, Wiesfleck, Schiefling), TEC ical (Altaussee, Schattendorf), try contao-events (Gmünd, Vorau). ~16 sources, zero code; verify each with `npm run crawl -- --url`.
4. **Decide on Citiesapps**: it hosts many of the larger Styrian/Carinthian towns (Bruck, Fürstenfeld, Radkersburg, Wolfsberg, Feldkirchen, Gleisdorf, Hartberg, Trofaiach). Their robots/legal header reserves TDM and aggregation without a licence. George should decide whether to request a licence (it@citiesapps.com) or rely on B1/B2 for those towns.
5. **Five tiny list parsers** for the big-town sites: Mürzzuschlag (EventBooking RSS, pubDate = start), Kapfenberg, Oberpullendorf (calendarize), Gröbming (Weblication), Stainz. Each is a ~30-line parser with selectors recorded in table A; Leoben (`div.event-item`) is next.

Caveats: robots check was my own light parser (Gemeinde24's `AIblock` heuristic hits were false positives from grouped User-agent blocks, not blocks of OkoloBot). Terms pages were not read in full for any site. The B3 (Kärnten) route is unverified.
